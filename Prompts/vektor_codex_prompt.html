VEKTOR — AI-Native Hedge Fund Frontend
This document is the canonical long-horizon build prompt for a Codex CLI agent. Each section below defines one self-contained Codex session. The agent must complete the full component, commit to codex/main with the prescribed commit format, and spin up the next session automatically. All sites are Next.js 14 (App Router), Tailwind CSS v3, TypeScript. Source components are copied from blog-next/ as the reference aesthetic. All new sites live in frontend-next/.

PROTO Codex Session Protocol — How Every Session Must Behave
System Instruction — Paste this as the Codex session preamble for every session
You are a senior full-stack engineer building the Vektor AI-native hedge fund frontend. SESSION MODEL: Every build item executes in TWO phases. PHASE A — IMPLEMENTATION Allowed: * Read repo * Read specifications * Read MCP memory * Create files * Modify files * Create mock data * Build components Forbidden: * npm run build * npm run lint * npm run dev * Playwright * git commit * git push Required output: IMPLEMENTATION COMPLETE HANDOFF PACKAGE Session: [ComponentID]A Files Created: [list] Files Modified: [list] Validation Required: * build * lint * dev * screenshot * logs * indexing Next Session: [ComponentID]B Validation PHASE B — VALIDATION Allowed: * npm run build * npm run lint * npm run dev * Playwright screenshot * Dev_Logs.md updates * knowledge_graph/events.jsonl updates * scripts/index-repo.ps1 * git commit * git push Required output: SESSION COMPLETE HANDOFF PACKAGE Session: [ComponentID]B Validation: PASS/FAIL Commit: [hash] Next Session: [next component] IMPORTANT: Never execute the next component. Always stop after generating the handoff package. The external orchestrator launches the next session.
⚠ Critical: The agent must NOT batch multiple components into one session. One session = one component. The "SESSION COMPLETE" print line is the signal for the orchestration layer to spin up the next Codex CLI process.
S1 Research Site — frontend-next/research-next/ 4 sessions

The research site is Vektor's public-facing academic and signal-intelligence hub. It mirrors the visual language of blog-next/ but is oriented around structured research publications — papers, quantitative reports, and AI-generated market signal summaries traceable to the underlying algorithm. Think a cross between arXiv, a quant hedge fund memo pad, and a CIO letter archive.

  • R1
    Project scaffold + shared components
    Init research-next/ with npx create-next-app (TypeScript, Tailwind, App Router). Copy Navbar, Footer, SiteNav, Typography tokens from blog-next/. Set up app/layout.tsx with global font imports and metadata. Configure tailwind.config.ts to match the Vektor color palette (near-black bg, sage green accent, warm parchment secondary). Create lib/types.ts with ResearchPaper and SignalReport TypeScript interfaces.
  • R2
    Research index page — app/page.tsx
    Hero section: "VEKTOR RESEARCH" headline, subtitle explaining AI-generated, algorithm-traceable publications. Below: two-column grid — left column lists "Research Papers" (academic PDFs), right column lists "Signal Reports" (weekly AI-generated market intelligence). Each paper card: title, authors, date, abstract excerpt (2 lines), category pill, and a "Read →" CTA. Minimum 6 mock papers and 4 mock signal reports. Include a category filter bar (All / Equities / Options / Macro / Crypto / Commodities) that filters the grid via React state. Include a search input that filters by title. All mock data hardcoded in lib/mock-research.ts.
  • R3
    Individual research paper page — app/paper/[slug]/page.tsx
    Full paper viewer. Left sidebar: paper metadata (title, date, authors, category, algo signal reference ID, model version used, data range). Main column: abstract, body rendered from mock MDX-style content object (5+ sections), and an "Algorithm Signal Trace" panel — a table mapping each conclusion in the paper to its originating signal (ticker, model, feature importance value, confidence score). Bottom: "Related Papers" horizontal scroll strip of 3 cards. Use generateStaticParams with the mock data slugs.
  • R4
    Signal Reports page — app/signals/page.tsx
    Grid of weekly AI-generated signal briefings. Each card: week ending date, headline market call (Bull/Bear/Neutral badge), asset class, confidence band (e.g. "68–74%"), top 3 signals listed inline, and "View Full Report →" link. A sticky sidebar on the left shows a "Signal Calendar" — a mini month calendar where weeks with reports are highlighted. Mock 8 signal report objects in lib/mock-signals.ts. Above the grid: a "Coverage" stats bar showing total papers published, average signal accuracy (mock %), and date of last update.
S2 Live PnL Site — frontend-next/livepnl-next/ 3 sessions

The Live PnL site is Vektor's public performance transparency page. Inspired by the Kite/Zerodha dashboard screenshot (dark bg, colorful holdings heatmap bar, equity + commodity split, market overview chart) but elevated to a professional hedge fund standard. The page should feel like a Bloomberg Terminal meets a modern SaaS dashboard. All data is mocked with realistic paper-trading numbers consistent with ALFRED's $100K paper portfolio.

    Project scaffold + shared components

Color palette: near-black bg (#0d0f14), accent green (#b8f09a), amber for gains (#f5c842), red for losses (#ff5f5f). Create lib/mock-pnl.ts with: portfolio summary object, holdings array (15 positions across equities/options/crypto/commodities), daily PnL time series (90 days), drawdown series, and benchmark comparison (SPY). All numbers consistent with a $100K starting portfolio.
  • P2
    Main dashboard — app/page.tsx
    Replicate and expand on the Kite screenshot layout:

    Top bar: Total portfolio value (large number), day PnL (green/red with %), total returns since inception, Sharpe ratio, max drawdown. Each in its own stat card.

    Holdings Heatmap Bar: A proportional horizontal bar where each segment is one holding, width = weight in portfolio, color = daily return (green gradient for gains, red for losses). On hover, show tooltip with ticker, weight, day PnL, current value.

    Asset Class Breakdown: Two side-by-side panels — Equities and Options — each showing allocated capital, margin used, open P&L, and a "View statement →" link. Add a third panel for Crypto and a fourth for Commodities.

    Performance Chart: A line chart (use Recharts) showing cumulative portfolio value vs SPY benchmark over 90 days. Toggle between 1W / 1M / 3M / All. Below chart: drawdown chart in red-fill area chart.

    Holdings Table: Expandable rows per asset class. Columns: Ticker, Asset Class, Qty, Avg Cost, LTP, P&L, P&L%, Weight, Status (Active/Pending/Closed).
  • P3
    Trade Log page — app/trades/page.tsx
    Paginated table of all paper trades executed by ALFRED. Columns: Date/Time, Ticker, Side (BUY/SELL), Qty, Price, Total, Strategy Tag (which algo signal triggered it), Slippage (estimated), Status (Filled/Pending/Cancelled). Filter by date range, side, asset class, strategy tag. Each strategy tag links to the relevant research paper on research.vektor.ai. Export button (non-functional, UI only). Above the table: a stats strip showing total trades, win rate, avg hold duration, best trade, worst trade — all mocked. Pagination: 20 rows per page.

TECH Technology Stack Constraints
Framework
Next.js 14, App Router, TypeScript strict mode. No Pages Router.
Styling
Tailwind CSS v3 only. No CSS Modules, no Styled Components, no Emotion.
Charts
Recharts for all data charts. SVG-only for diagrams (no D3, no Nivo).
Data
All mock data in lib/mock-*.ts files. No real API calls in this phase.
Components
Base components copied from blog-next/. Adapt, don't rewrite from scratch.
Icons
Lucide React only. No Heroicons, no FontAwesome, no inline SVG icon paths.
State
React useState + useEffect for UI state. No Redux, no Zustand in this phase.
Fonts
next/font with Google Fonts. Use JetBrains Mono for monospace data, Syne for headings.
✕ Absolutely prohibited: MUI, Chakra UI, Ant Design, shadcn/ui (in this phase), React Query, SWR, Prisma, or any ORM. No pages/ directory. No getServerSideProps or getStaticProps (use App Router conventions only).
